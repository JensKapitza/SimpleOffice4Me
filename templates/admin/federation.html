Dokument-Berechtigungen
Mail-Vorgang-Federation
Standard ist aus. Für den Versand von Mail-Vorgängen benötigt der Peer zusätzlich eine HTTPS-Adresse, direkten Trust, ausgehandelte v3-mail_cases-Capability und eine explizite Benutzerzuordnung. IMAP-/SMTP-Zugangsdaten werden nicht übertragen.
Rendezvous-Vermittlung
Standard ist aus. Der Relay übermittelt nur kurzlebige Verbindungsnachrichten an dort aktiv konfigurierte Peers. Er erteilt weder Trust noch Aktivierung oder Datenrechte und ist kein Datei- oder TLS-Relay.
Teilt nur Peer-Name, Richtung und Erreichbarkeitsstatus; keine Adresse, Fehlerdetails, Latenz oder Netzwerkroute. Standardmäßig nur für Administratoren sichtbar.
Erweiterte Policy
Die sichtbaren Dokument- und Mail-Vorgang-Berechtigungen oben werden beim Speichern in die zugehörigen Policy-Bereiche übernommen.

Netzwerkdiagnose verstehen

DNS prüft die Auflösung des konfigurierten Peer-Hosts; TCP den Socket-Aufbau; TLS Zertifikat und verschlüsselte Verbindung; HTTP die Antwort; Auth Peer-Identität und signierte Probeantwort.

„Server → konfigurierte Peer-Adresse“ misst nur den ausgehenden Weg von dieser Instanz. „Eingehende authentifizierte Anfrage“ erscheint erst, wenn der Peer selbst eine signierte Diagnoseanfrage an diesen Server sendet. Das ist ein Nachweis für genau diesen eingehenden Netzwerkweg zum Prüfzeitpunkt, aber keine aktiv vom Server angeforderte Gegenprüfung. Beides beweist keine öffentliche Erreichbarkeit und leitet keinen NAT-, Tunnel- oder Relay-Pfad ab.

Browserprüfung ist eine getrennte Best-effort-Client-Sicht. CORS, CSP, Mixed Content, TLS und Browserrichtlinien können sie unauswertbar machen; daraus wird kein Offline-Status abgeleitet. Veraltete Ergebnisse sind älter als fünf Minuten.
